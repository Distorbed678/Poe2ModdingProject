# History

What was built when, newest last. Detail lives in the topic docs linked from each line; the open work is at the end. Terrain progress is in [terrain.md](terrain.md).

- **2026-10-12, foundation and login.** Repo, tools, workspace, config, data access (Bundles2 and `.datc64`), the `version.dll` proxy and deploy tooling. The DLL loads under Proton, the client reads our gateway entry and the server logs its first message. Login works end to end: key exchange (DLL crypto bypass), authentication by machine hash, character creation and selection, Standard and Hardcore leagues ([../protocol/login.md](../protocol/login.md), [../re/crypto.md](../re/crypto.md)).
- **2026-10-13, first zone.** Play, hand-off, encryption, area info, inventories, player entity and initial state; the Ranger stands in Clearfell Encampment and a new character lies under the Riverbank intro tree, with default stats from game data ([../protocol/instance.md](../protocol/instance.md), [../protocol/entities.md](../protocol/entities.md)). The invisible-player bug was the frame length of InitialState. The same day: start position on the Riverbank shore ([../architecture/instance-world.md](../architecture/instance-world.md)), character deletion, exit to character selection with a resume ticket, login and instance heartbeats, pause, chat joins, "full access", non-Steam shortcut ([../guides/setup.md](../guides/setup.md)).
- **2026-10-14, movement.** WASD, click-to-move and the dodge roll, pause stops the server simulation, area and position are saved on exit ([../protocol/movement.md](../protocol/movement.md)). Follow-up after play-testing: lag traced to the server (slow A*, undecoded steering messages), position sync from the DLL, smoother turns, held click-to-move, "exit to log in screen", second-character creation.
- **2026-10-14, debug suite.** The DLL split into a permanent loader and a hot-reloadable core with a Vulkan imgui overlay, packet capture and snapshots, and read-only operation on official servers ([../architecture/client-dll.md](../architecture/client-dll.md)). Official sessions were captured 2026-10-14/15 and compared with ours ([../re/captures.md](../re/captures.md)).
- **2026-10-15, facing and terrain tooling.** The player faces the cursor. Terrain generator tooling: area export with hash self-check, generator trace, seed sweep ([../re/terrain/README.md](../re/terrain/README.md)); the server's generator reproduced Clearfell and the Riverbank.
- **By 2026-10-16, dungeon layouts.** `.dgr` areas ported (G1_3, G1_6 to G1_9; [../re/terrain/dungeon.md](../re/terrain/dungeon.md)).
- **2026-10-17, instances, transfers, chat.** Instance directory, transfers between instances, forced layouts, the Instances page, chat channels, server commands in chat and the overlay, overlay sidebar and command palette ([../guides/server-admin.md](../guides/server-admin.md)). Multiplayer gap analysis ([../guides/hosting.md](../guides/hosting.md)).
- **2026-10-20, restructure.** Docs, scripts and runtime data moved into the current layout; protocol and client hook split into submodules; datamined outputs moved to `dumps/` ([../plans/orchestration-2026-10.md](../plans/orchestration-2026-10.md)).
- **2026-10-20, movement verified in game.** The drift checker against the real client: WASD, rolls (standing, walking, sprint), click-to-move and held click. Found and fixed: the server's roll ended at the first blocked step, and rolls used a taper that does not fit sprint rolls (per-frame official tables now, [../protocol/movement.md](../protocol/movement.md#roll-path-and-speed-profile)); a plain `0x20` test key sends no roll steering, use `indown:`/`inup:`. Open: the client's own slow-down after a sprint without stream and its first-frame roll heading (gaps #11, #12).
- **2026-10-20, server-authoritative movement.** The movement spec from the official captures (skill acknowledgements, roll/sprint/WASD/aim sequences with frame timing, gap list), then `poe-game` (`World`, `GridSource`, the `Locomotion` component that emits the official reply events, replay tests from capture fixtures) and the instance-server glue. The server owns the player's position; the DLL's position reports only feed the opt-in drift checker (`[dev] drift_check`). The cursor/turn workarounds and their config keys are gone ([../protocol/movement.md](../protocol/movement.md), [../architecture/instance-world.md](../architecture/instance-world.md)).
- **2026-10-20, accounts and the standalone login.** RE of the platform getter ([../re/standalone-login.md](../re/standalone-login.md)); `poe-accounts` with passwords (argon2id over the client's digest), roles, disable and per-cluster rolling tokens (migration `0006`), `0x0003` credentials in the login server, the DLL's `login_mode = "standalone"` patch and `trusted_servers`, patcher skip via `--success-event 0`. Password and remember-me logins verified in game ([../architecture/accounts.md](../architecture/accounts.md)). Config reorganised (`[network.*]`, merged `[instance]`, `[dev]`, `[cluster]`, `[web]`; [../guides/setup.md](../guides/setup.md#config-migration-2026-10)); the README tracker is generated from `tracker.toml`.
- **2026-10-20, remote readiness.** Terrain layout and grid upload over the instance TCP port, the HMAC-authenticated per-session side channel (`PSS` v1) replacing the loopback datagrams, `[network.login] public_port`, a loopback `public_host` warning ([../guides/hosting.md](../guides/hosting.md), [../protocol/side-channel.md](../protocol/side-channel.md)).
- **2026-10-20, web API and web admin.** `poe-web-api` (axum REST and WebSocket log inside `poe-server`, OpenAPI), the Poe2WebAdmin SPA as submodule `modules/web-admin` ([../architecture/web-api.md](../architecture/web-api.md)).
- **2026-10-20, launcher.** Poe2Launcher (Tauri 2 + Svelte 5) as submodule `modules/launcher`: server profiles, login through the web API, Steam depot install (not run for real yet), deploy and Play, mod install; `POST /api/v1/game-token` for auto-login ([../guides/launcher.md](../guides/launcher.md)).
- **2026-10-20, remote players and the instance actor.** Other players decoded from an official town capture ([../protocol/entities.md](../protocol/entities.md)); one task per instance owns one `World` shared by all its sessions, with remote `AddObject` on join, same-frame relay of every entity event and the official leave sequence ([../architecture/instance-world.md](../architecture/instance-world.md#the-instance-actor-wp36)).
- **2026-10-21, multiplayer verified.** Two real clients over a LAN IP (`scripts/test-mp.sh`): token logins through the trusted-remote path, both in one instance and visible to each other, walk and roll relayed, chat, the leave sequence on a transfer, a duplicate login ending the first session. Found and fixed: `InitialState` flags `7` froze towns, towns now get `04` ([../guides/hosting.md](../guides/hosting.md#local-two-client-test)).
- **2026-10-21, consistency pass and terrain plan.** Comments describe current behaviour; the docs were checked against the code. The terrain handoff plan and the area x topology x orientation matrix (`cargo xtask terrain-matrix`) for the port to all areas ([../plans/terrain-all-areas.md](../plans/terrain-all-areas.md), [terrain.md](terrain.md)).
